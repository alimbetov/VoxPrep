# Full native demo

Run `./scripts/local/flutter-full-demo.sh` on macOS. The main `lib/main_demo.dart` composes the actual learner UI with local demo gateways, a separate `voxprep_full_demo_v2` Drift database, in-memory demo installation credentials and bundled assets. It is debug-only.

The sample has eight learning paths, three representative topic lessons with full text sections, two short assessment fixtures, three original geometric covers, and one four-second Piper MP3 attached to Professional communication basics (AWS and other shared-content paths). This is a functional sample, not eight complete courses. Translation-language choices are mocked; translated lesson bodies are not supplied. Billing simulation is development-only, not a real purchase.

Open Learn → Java Interview → goal → track → collection → Explaining dependency injection for the text and image. For audio use Learn → AWS → goal → track → collection → Professional communication basics. The bundled audio says “I build reliable services and verify recovery paths”; it is a speaking example, not a narration of the entire lesson. The audio was generated by the real local Piper/LJSpeech A3 run, job `dfa6fd6a-b180-43c5-9952-5b11222aeb8f`.

`assets/demo/` ships PNG/MP3 bytes; `DemoAssetByteSource` serves only known bundled IDs. Normal SHA and size validation, storage, cover resolution and playback remain active. Covers are generated by `tool/generate_demo_covers.py` using Pillow and a macOS Arial font. No credentials are bundled. The production entrypoint remains separate.

The browser at port 3000 runs the separate lightweight `demo_web_main.dart` showcase. It is not this native application. Start it using `./scripts/local/flutter-demo.sh`.

Validation: demo graph/widget tests; `demo_assets_test.dart` checks all bundled assets against manifest SHA/size and verifies lesson bodies and cover/audio bindings. This does not qualify A4 production HTTP/offline acceptance.
